# v1.3.0 UL 候选退出门证据

> 状态：候选退出门本地证据已满足，等待跨平台 CI 与 Human Gate。正式 tag、release 与 `shadow -> warn/enforce` 晋升不由本文件自动触发。

对应 [roadmap 候选退出门](./roadmap.md#v130dev0-candidate--portable-runtime--ul) 的四条条款，本轮（2026-08-07 仓库升级批次）产生以下可核查证据。

## 条款 1：至少两个结构不同的 AI 工程任务证明 UL 能改善失败归因或减少混杂修改

### 任务 A：跨 skill 深度 eval 资产工程

为 `paranoia-ai-system-evolver` 与 `game-design-source-curator` 补齐 `evals.json`、`rubric.yaml`、`negative_cases.md`（此前两个 skill 只有五门 behavior fixture）。

```text
ul_state（摘要）
current_rung: UL-L2（固定输入环境内的受控组合）
released_this_round: eval 内容设计（唯一主要变量）
held_constant: eval 文件格式契约（沿用 game-experience-analyzer 三件套结构）、
               behavior_evals.json 与 SKILL.md 不动、
               run_behavior_evals.py 与 validate_repo.py 的既有校验规则不动
consequence_budget: 新增文件失败可直接删除；不触碰任何既有断言
预注册信号: pass=单文件评测与 --all-packaged 全绿；
           fail=断言误报或 suites 统计异常；
           confounded=多个文件同时修改导致无法定位断言失败源
```

结果：`paranoia` 11 evals、`curator` 8 evals 一次通过；`--all-packaged` 从 9 suites / 53 evals 升到 11 suites / 72 evals，全绿。

UL 对失败归因的实际改善（一个真实案例）：在写入任何文件之前，按 UL-L0（source contract 先行）读取了 `run_behavior_evals.py` 的 fixture 发现契约——`evals.json` 只有在全部 case id 都存在于 `synthetic_outputs.json` 时才会进入 `--all-packaged` 统计。若跳过这一步直接写文件，新 eval 会被静默跳过（CI 显示绿色但从未执行），这是典型的不可归因静默失败。UL 的先固定环境、再释放变量纪律把这个失败模式在发生前消除。

### 任务 B：runtime 核心 gate/graph 单元测试工程

为 `gamedesignos/project_ready.py`（1552 行核心）补 `scripts/tests/test_project_ready_gates.py`。

```text
ul_state（摘要）
current_rung: UL-L1 -> UL-L2（先原子识别 gate 分支语义，再受控组合成测试）
released_this_round: 测试内容本身（唯一新变量）
held_constant: 不改任何 runtime 源码；复用 test_runtime_cli.py 已验证的
               workspace fixture 构造模式；沿用 unittest 框架不引入新测试栈
consequence_budget: 测试文件独立，失败不影响既有 41 项测试
预注册归因协议: 若断言失败，先用 canonical schema 与 _normalize_decision
               源码仲裁"测试理解错误"还是"发现真实缺陷"，禁止两头同时改
```

结果：34 个测试一次通过，覆盖 6 种 gate 的 19 个分支、`next_best_action` 优先级序、`graph_edges`/`inspect_graph`/Mermaid 导出与 gate 写盘持久化。`gamedesignos` 包 coverage 基线：**总体 81%，project_ready.py 89%**（`python -m coverage run --source=gamedesignos -m unittest discover -s scripts/tests`）。

### 证据强度的诚实边界

两个任务结构不同（eval 资产生产 vs 代码测试工程），且都体现了"单变量释放 + 显式保持变量"对混杂修改的抑制：全程零回滚、零试错循环、没有一次把多个未验证修改同时提交。因此满足条款 1 中"减少混杂修改"这一可选判据。两个任务都一次通过，**没有产生"失败发生后按协议归因"的实战样本**；不能把本证据扩大解释为失败归因协议已经过真实故障验证。

## 条款 2：至少一个 negative-transfer 用例证明 UL 不劫持普通任务

两类证据：

1. **实操观察**：同批次的黄金样例生成任务（`examples/golden-lighthouse/workspace`，普通领域任务而非 AI 工程任务）全程未套用 UL 表单，按"生成 -> 检查 -> 文档"三步直接完成，无额外描述成本。UL 未越界渗入普通 workspace 生成流程。
2. **固化回归**：`paranoia-ai-system-evolver/evals/evals.json` 新增 `pase_misroute_domain_skill`（领域任务必须转交领域 skill，治理层不接管）与 `negative_cases.md` Case 8（接管领域产出/宣称泛化判为失败），把"UL/治理层不劫持领域曲线"写成可重复执行的静态断言，已进入 `--all-packaged` CI 路径。

## 条款 3：schema、workflow 引用、source checkout、wheel snapshot 与 installed-wheel smoke 一致

由既有 CI 流水线覆盖（validate_repo -> unittest -> packaged evals -> agent skills -> CLI smoke -> build -> sdist rebuild -> installed wheel smoke）。本轮升级后的全量本地验证结果见 CHANGELOG 与本批次提交说明；跨平台矩阵以 GitHub Actions 实际运行为准。

## 条款 4：新增描述成本没有超过其减少返工与错误归因的收益

本轮总描述成本变化：

| 方向 | 内容 |
| --- | --- |
| 新增 | 6 个 eval 资产文件（2 skill x 3 件套）、1 个测试文件（34 用例）、1 个三语言镜像校验函数、1 份黄金样例 workspace（23 个只读 JSON/MD）、本证据文档 |
| 删除 | 4 个死目录（`.agents/`、`.codex/`、`articles/`、`.tmp/`） |
| 迁移 | 无复杂度跨层迁移；新增均落在 eval 与 validation 层，未增加 core model 或 routing 成本 |

收益：两个此前零深度回归的 skill 获得 19 个可执行断言；runtime 核心从"仅集成测试"升级为"分支级单元回归 + coverage 基线"；三语言漂移从"人工记忆"变为"CI 拦截"；GitHub 浏览者获得免安装可检视的完整证据链样例。评估结论：净收益为正。
