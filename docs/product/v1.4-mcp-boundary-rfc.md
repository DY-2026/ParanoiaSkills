# GameDesignOS v1.4 MCP Boundary RFC

> - 状态：`candidate`
> - 协议目标：MCP `2026-07-28`
> - 证据日期：2026-08-15
> - 当前实现：只读 Application Service 已落地；MCP server、SDK 依赖、host 配置均未落地
> - 权限结论：本 RFC 不授权写入工具、发布、账号操作、项目承诺或 Human Gate 代签

## 1. 决策摘要

GameDesignOS 下一步可以增加本地 MCP 适配器，但第一阶段只应是 `stdio-first`、单工作区、只读、无模型、无密钥的薄适配层：

```text
CLI ───────────────┐
                   v
              Application Service -> Workspace / Contracts / Domain Gates
                   ^
MCP stdio adapter ─┘
```

CLI 与未来 MCP 必须复用同一组 Application Service。MCP 只负责协议编解码、能力声明、输入校验、输出脱敏与错误映射，不复制路由、状态、Gate、图谱或验证逻辑。

这一边界延续 [DeepSeek Harness 工程适配审计](../2026-08-15-deepseek-harness-engineering-fit.md) 中“稳定核心、host 薄适配、语义检查点”的吸收项，但不把外部 harness、模型网关或执行循环搬入核心 runtime。

## 2. 事实、推断与待实证

### 2.1 当前项目事实

- Workspace 与 canonical contracts 仍是项目真源；MCP 不创建第二份状态。
- `gamedesignos/application/project_queries.py` 已提供确定性只读查询，CLI 已开始复用。
- 当前 runtime 没有 MCP server、没有 `mcp` SDK 依赖、没有 hosted API，也没有模型或密钥管理。
- `preview_gate` 固定以 `write=False` 执行；它不得产生 `.gamedesignos/gate-results/` 文件。
- v1 `status` 已改为读取 `01-decisions/DEC-*.json`，不再只读取兼容层 decision log。

### 2.2 MCP 官方事实

- `2026-07-28` 版本采用无协议 session 的 stateless core；请求携带自己的协议、客户端与能力信息，可选 `server/discover`，应用状态应使用显式 handle，而不是隐藏 transport session。
- `tools/list`、`prompts/list`、`resources/list` 与 `resources/read` 支持 cache hints；Roots、Sampling 与协议 Logging 已弃用，新实现不应采用。
- 官方本地安全建议优先使用 `stdio` 限制访问面，并要求客户端展示完整启动命令、获得明确同意、使用最小权限和沙箱。
- HTTP transport 会引入授权、DNS rebinding、issuer、scope 与 token audience 等额外边界；当前本地只读目标不需要先承担这组成本。
- 官方 Python SDK v2 面向 `2026-07-28`，但 host 支持仍需真实矩阵验证，不能只凭 SDK 文档宣称兼容。

官方依据：

- [MCP 2026-07-28 specification announcement](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- [MCP 2026-07-28 security best practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)
- [MCP Python SDK v2 notes](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/whats-new.md)

### 2.3 项目推断

- `stdio-first` 是对“本地单用户、显式启动、无远程账号”约束的最小实现，不是 MCP 对所有场景的唯一答案。
- alpha 不需要协议级身份系统；用户对完整启动命令与工作区路径的确认，就是本地连接的 Human Gate。
- 每次调用都应显式绑定 server 启动时锁定的 workspace handle；不能依赖隐藏 session，也不能让模型传入任意绝对路径。
- SDK 版本只有在 host matrix 通过后才可 pin；本 RFC 阶段不增加依赖。

### 2.4 待实证

- Codex、Claude Desktop、VS Code 等目标 host 对 `2026-07-28`、structured output、resource template、cache hints 与错误展示的实际支持。
- 私有 workspace 内容经过本地 host 上下文后是否符合用户的隐私预期。
- MCP 比直接 CLI 是否显著减少接入成本、错误解析或上下文丢失。
- 只读 P0 的实际使用频率是否足以支付新增协议表面的维护成本。

## 3. P0 目标与非目标

### 3.1 目标

1. 让支持 MCP 的本地 agent host 可读取一个明确授权的 GameDesignOS workspace。
2. 让 CLI 与 MCP 对相同输入返回等价的结构化结果。
3. 保持路由、状态、验证、Gate preview 与图谱完全确定性。
4. 不改变 workspace schema `1.0.0`，不迁移既有项目。
5. 让适配器可整体移除，而不影响 CLI 与 Application Service。

### 3.2 非目标

- 不执行模型调用、sampling、prompt chaining 或 multi-agent orchestration。
- 不提供 HTTP server、远程托管、OAuth、账号或 token passthrough。
- 不开放写入、删除、发布、付款、权限、scope lock 或项目承诺工具。
- 不用 MCP 取代 CLI、skills、contracts 或 workspace。
- 不声称任何 host 已兼容，直到 matrix 产生可回放证据。

## 4. P0 能力面

### 4.1 Resources

server 启动时只能绑定一个已解析并确认的 workspace 根目录。对模型暴露逻辑 URI，不暴露本地绝对路径：

| URI | 内容 | 缓存建议 |
| --- | --- | --- |
| `gamedesignos://workspace/current/manifest` | 经过 allowlist 的项目元数据与版本 | workspace 文件变化前可缓存 |
| `gamedesignos://workspace/current/status` | 状态、兼容性、Decision 与 Gate 统计 | 短缓存 |
| `gamedesignos://workspace/current/decisions` | normalized Decision Objects | 短缓存 |
| `gamedesignos://workspace/current/assumptions` | Assumption Registry | 短缓存 |
| `gamedesignos://workspace/current/evidence` | Evidence Ledger 与边界 | 短缓存 |
| `gamedesignos://workspace/current/experiments` | 计划、结果与 review 状态 | 短缓存 |
| `gamedesignos://workspace/current/graph` | 本地 Decision Graph | 短缓存 |
| `gamedesignos://contracts/{name}` | packaged canonical contract | 版本内长缓存 |
| `gamedesignos://skills/{name}/metadata` | 公开 skill 元数据，不读取私有安装状态 | 版本内长缓存 |

Resource presenter 必须去除 `_path`、绝对路径、未列入 schema 的字段、环境变量、`.git`、`.env`、密钥文件和任意 inbox 原文。`source_status`、`confidence`、`unsupported_claims` 与 review state 不得丢失。

### 4.2 Read-only Tools

| Tool | Application Service | 写盘 |
| --- | --- | --- |
| `route_task` | `route_project_task` | 否 |
| `project_status` | `get_project_status` | 否 |
| `project_health` | `get_project_health` | 否 |
| `next_action` | `get_next_action` | 否 |
| `inspect_decision` | `inspect_project_decision` | 否 |
| `inspect_evidence` | `inspect_project_evidence` | 否 |
| `inspect_graph` | `inspect_project_graph` | 否 |
| `export_graph` | `export_project_graph` | 否 |
| `validate_workspace` | `validate_project_workspace` | 否 |
| `preview_gate` | `preview_gate` | 否，强制 `write=False` |

所有 tools 使用 JSON Schema 2020-12 输入与 structured output。业务错误必须返回稳定的错误码、可读消息和可恢复建议，不输出 Python traceback。

建议的稳定错误码：

```text
workspace_not_found
workspace_out_of_scope
incompatible_workspace
record_not_found
invalid_argument
validation_failed
internal_error
```

`internal_error` 对 host 隐藏本地路径与堆栈；完整诊断只写 `stderr`，`stdout` 保留给 MCP 协议。

## 5. 明确禁止的 alpha 工具

以下能力不进入 alpha catalog：

```text
decision_accept
decision_reject
decision_supersede
scope_lock
publish / export_public
delete / move / overwrite
spend / purchase / payment
change_permissions
promote_learning_to_rule
run_model / sampling
execute_skill_automatically
```

隐藏工具描述不是权限控制。未授权能力必须不存在于 server tool registry，也不能通过一个通用 `run_command`、`write_file` 或 `call_cli` 旁路出现。

## 6. P1 写入候选，不在本轮实现

只有 P0 host matrix 和无写入证明通过后，才评估以下 draft-only 工具：

- `create_draft_decision`
- `create_draft_assumption`
- `register_evidence`
- `create_experiment_plan`
- `record_experiment_result`
- `write_design_asset_draft`

每个候选必须同时具备：精确目标、schema 校验、preview/diff、来源状态、显式授权事件、原子写入、file-scoped rollback、幂等键与失败后 `outcome_unknown` 处理。即使未来开放 draft 写入，Decision accept/reject/supersede、发布、删除与权限变化仍是独立 Human Gate，不随 draft 权限自动获得。

## 7. 安全与权限边界

### 7.1 工作区锁定

- 启动配置接收一个 workspace 路径；host 必须向用户展示完整命令与路径。
- server 启动后解析 real path，并确认存在 `game.designos.yaml`。
- tool 参数不得接收 filesystem root、任意 path、glob 或 shell command。
- 所有内部文件访问都必须 resolve 后仍位于锁定 workspace 或 packaged read-only resources 内。
- symlink、junction 与 `..` 逃逸需要负向测试。

### 7.2 进程与网络

- P0 使用 direct `stdio`，不启动 localhost 监听端口。
- P0 默认无网络，不读取 API key，不接受或转发 bearer token。
- server 不调用 shell，不启动子 agent，不执行 workspace 内容。
- protocol 输出只走 `stdout`；日志和诊断只走 `stderr`，且不得包含私密正文或密钥。

### 7.3 状态与授权

- 不使用隐藏 transport session 保存项目状态。
- workspace handle 来自启动配置，不由模型临时选择。
- 无授权中断流程依赖：P0 只读，所以不采用 MRTR 来索要写权限。
- enable MCP 配置本身是 Human Gate；未来每类写权限还需独立、可撤销的权限事件。

## 8. SDK 与 Host Matrix

本 RFC 不 pin SDK。实现 spike 时优先验证官方 Python SDK v2，但只有满足下表后才可进入依赖与 package metadata：

| Host | Transport | 协议观察值 | Resources | Structured Tools | 错误展示 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| Codex | stdio | 待测 | 待测 | 待测 | 待测 | `needs_more_evidence` |
| Claude Desktop | stdio | 待测 | 待测 | 待测 | 待测 | `needs_more_evidence` |
| VS Code | stdio | 待测 | 待测 | 待测 | 待测 | `needs_more_evidence` |

实现可以借助 SDK 同时服务旧协议客户端，但不得自行维护两套协议业务逻辑。兼容性事实必须记录 host 版本、SDK 版本、协议观察值、fixture、失败输出与日期。

## 9. 验收门

P0 只有全部满足才可从 `candidate` 晋升：

1. CLI / Application Service / MCP 对同一 fixture 的语义结果一致。
2. 连续调用全部 P0 Resources/Tools 后，workspace 文件哈希与目录清单不变。
3. `preview_gate` 不产生 gate-result 文件；tool catalog 中不存在通用写入或禁用工具。
4. 绝对路径、`..`、symlink/junction、未知 workspace handle 均被拒绝。
5. 私密路径、环境变量、token、traceback 与非 allowlist 字段不进入 MCP 输出。
6. stdout 无日志污染，取消、无效参数和 client disconnect 不损坏进程或 workspace。
7. source checkout、wheel、sdist rebuild 与 installed-wheel smoke 一致。
8. 至少两个真实 host 通过 fixture matrix；失败项保持 `partial` 或 `needs_more_evidence`。
9. 用户明确确认安装命令、工作区范围和当前只读权限。
10. 描述成本审计证明新增 adapter 没有复制业务逻辑，也没有让普通 CLI 使用变复杂。

## 10. Rollback

- MCP adapter 必须是独立可选模块与 entrypoint；删除模块和 optional dependency 即可回滚。
- CLI 与 Application Service 不依赖 MCP SDK，回滚 adapter 后仍可完整工作。
- 不迁移 workspace schema，不写 MCP 专属状态，因此无需回滚用户项目数据。
- host 配置由用户显式移除；GameDesignOS 不替用户修改全局 host 配置。

## 11. 未采用方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| MCP tool 内调用 CLI subprocess | 不采用 | 重复解析文本/退出码，取消与结构化错误脆弱，且增加进程成本。 |
| HTTP-first server | 不采用 | 当前没有远程共享需求，却提前引入监听面、OAuth、DNS rebinding 与 token 边界。 |
| MCP 内置模型网关或 sampling | 不采用 | 违背 local deterministic core，扩大密钥、费用与结果归因范围。 |
| 为 MCP 重写 domain/runtime | 不采用 | workspace、contracts、gates 与 routing 已可复用；重写会制造第二真源。 |
| alpha 同时开放读写 | 不采用 | 无 host evidence、权限事件、diff、rollback 与 outcome recovery，不满足 Human Gate。 |

## 12. 描述成本审计

当前新增成本限于一组薄 Application Service 和一份边界 RFC；没有新 schema、daemon、SDK、host 配置或 workspace 字段。下一阶段如果 MCP adapter 不能保持“协议薄层、核心零复制”，或不能用 host matrix 证明比 CLI 更稳，则停止推进，不因协议流行度扩大范围。
